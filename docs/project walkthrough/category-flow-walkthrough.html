1. Enter a category route

GET /category/:category is public. The controller trims and matches the parameter case-insensitively against World, Business, Technology, Science, Culture, Sports, Opinion. /category/technology renders Technology without a canonical redirect; invalid category falls through to centralized 404. The legacy /technology redirect has been removed; /technology now reaches the centralized 404 handler.

Sources: routes/pages.js, controllers/pageController.js, config/constants.js, middleware/errorHandler.js.

2. Database reads and view mapping

Two reads run in parallel: published-category articles sorted publishedAt descending, limited to 20, populated reporter username/displayName and lean; and countDocuments for the same filter. Filter is isPublished:true plus publishedVersion.category, not status=published. An approved story stays here during draft/pending/returned updates. Cards use only published content and session viewedArticles for seen flags. The shared reporterName helper supplies displayName, then username, or Unknown for a deleted reporter; readingLabel estimates published-body reading time at 200 words per minute, rounded with a one-minute minimum.

Sources: controllers/pageController.js, models/Article.js, config/constants.js, utils/viewMappers.js.

3. Initial complete HTML and script startup

EJS renders shared head/public header, category breadcrumb/title/description/count, either first-page cards with hidden category and sentinel or empty-state block, then public footer. Shared head loads style.css and deferred api.js; feed.js is deferred at the end. There is no weather widget/script or initial category JSON fetch. Category rules in pages.css supply one card column below 768px, two from 768px, and three from 1024px; shared components.css styles cards and layouts.css supplies the public header offset. IntersectionObserver may nevertheless request page 2 immediately if its sentinel is already within the 400px margin.

Sources: views/pages/public/category.ejs, views/partials/shared/head.ejs, public/css/style.css, public/js/feed.js, public/js/api.js, public/css/pages.css, public/css/components.css, public/css/layouts.css.

4. Logo, navigation, and mobile menu

Logo and Home open /; Search opens /search. The details/summary mobile menu toggles natively and causes no request until a link is followed. Mobile menu always includes Staff Login, even for authenticated sessions; desktop actions are session-aware. These are full document navigations, not feed filters.

Sources: views/partials/public/header-standard.ejs, views/partials/shared/site-logo.ejs, controllers/pageController.js, routes/pages.js.

5. Header search form

Header search starts blank on category pages and submits ordinary GET /search?q=TEXT, browser-encoded through name=q. feed.js does not attach to siteSearch; category has no feedSearch control. Submitting navigates to a new search-results document rather than narrowing this grid.

Sources: views/partials/public/header-standard.ejs, views/pages/public/category.ejs, public/js/feed.js, controllers/pageController.js.

6. Staff actions and sign out

Guests see Staff Login → /staff/login. Session users see Newsroom → Editor queue or Reporter dashboard plus Sign Out. Logout POST /api/auth/logout disables the button; success destroys session, clears connect.sid and navigates home, failure silently restores it. Viewing a category is not an article-view increment. Public category/header rendering reads the session directly; it does not refresh the user role from MongoDB. The protected newsroom destination re-reads the account role before granting access, so this link is not authorization and can reflect an older session role.

Sources: views/partials/public/header-standard.ejs, public/js/api.js, controllers/authController.js, server.js, middleware/auth.js, controllers/pageController.js.

7. Breadcrumb, title, and category description

Breadcrumb Home navigates /. Current category is static text. Category Beat, canonical title and configured descriptive copy render from controller locals with escaped EJS. Template has a fallback description if none supplied. They are not editable controls and do not change when additional cards arrive.

Sources: controllers/pageController.js, views/pages/public/category.ejs.

8. Total category article counter

The count is the exact countDocuments result for all published articles in this category, not the initial 20 or number currently loaded. EJS chooses article only when count===1. Later feed JSON contains no total and feed.js never updates this header. Concurrent publishing/deletion can make the displayed snapshot stale.

Sources: controllers/pageController.js, views/pages/public/category.ejs, public/js/feed.js.

9. Server-rendered article cards

Each shared article-card is one article link /articles/ID. Optional lazy image uses published image URL/title alt; summary optional; category, publication date/time, title, reporter displayName/username, views and reading label render escaped. Title/category/author fallbacks are provided by controller/template. Clicking any part of card navigates to the public article and that controller handles public view tracking.

Sources: controllers/pageController.js, views/partials/public/article-card.ejs, utils/viewMappers.js, views/pages/public/category.ejs.

10. Read badge and session history

Initial cards set data-seen and show Read when their ID is in req.session.viewedArticles. API cards derive seen from the same session snapshot using string IDs. No read/unread selector appears on this page, despite feed.js supporting a feedSeen control elsewhere. Reading another tab does not locally refresh badges; revisiting this document or fetching another page uses later session data.

Sources: controllers/pageController.js, controllers/articleController.js, views/partials/public/article-card.ejs, public/js/feed.js.

11. Hidden category and feed state

feedCategory is a hidden input holding canonical category. It pins subsequent requests; there is no visible category/sort/search/read filter on this page. feedGrid starts data-page=1 and data-has-more. Script copies these into variables page/hasMore plus loading=false and requestId=0; later state updates are variables, not rewritten data attributes.

Sources: views/pages/public/category.ejs, public/js/feed.js, controllers/articleController.js.

12. Infinite-scroll trigger

IntersectionObserver watches feedSentinel with rootMargin 400px. On an intersecting callback, hasMore && !loading starts load(page+1,false). Only one request runs at a time through loading. If the browser lacks IntersectionObserver, there is no load-more button, scroll fallback, or pagination link. End of feed keeps observer attached but hasMore prevents further requests.

Sources: public/js/feed.js, views/pages/public/category.ejs.

13. Feed request and actual response contract

Example GET /api/articles/feed?page=2&category=Technology. Public route queries isPublished:true, validates category with exact configured membership, sorts publishedAt descending with _id descending as a tie-breaker, skips (page-1)*20, limits 20, populates reporter and selects card fields. Returns {page,hasMore,articles:[{_id,title,summary,category,imageUrl,imageAlt,dateLabel,datetime,views,readLabel,reporterName,seen}]}. The database projection now includes publishedVersion.content to calculate readLabel, but the raw content and total are not returned. Appended cards therefore include the same reading-time label as initial cards. Shared reporterName formatting is used in both render paths. The feed’s optional title-search filter uses escapeRegex from utils/queries.js; this page supplies no search input to that filter. Invalid direct API category is ignored rather than category-route 404.

Sources: routes/articles.js, controllers/articleController.js, config/constants.js, utils/viewMappers.js, utils/queries.js, public/js/api.js, public/js/feed.js.

14. Appending cards and updating feed status

Loading articles… appears through api.flash. Success uses escapeHtml in cardHtml and insertAdjacentHTML(beforeend), then assigns response page/hasMore. Existing cards remain. Empty grid shows No articles match your search.; nonempty and no more shows You have reached the end of the feed.; otherwise status hides. It does not deduplicate IDs, refresh initial cards, update total, or change URL/history.

Sources: public/js/feed.js, public/js/api.js, views/partials/public/article-card.ejs, views/pages/public/category.ejs.

15. Errors, exact page boundaries, and concurrency

Request failure flashes error and releases loading; page/hasMore remain prior values, so a later observer callback may retry the same page. There is no explicit retry button or timer; if intersection does not change, another callback is not guaranteed. With exactly 20 initial cards hasMore=true, so an extra request can return zero and mark end. The API now has an _id tie-breaker, but the initial category query still sorts only publishedAt. Equal publication timestamps can therefore order differently across the initial HTML and later API pages. Offset pagination and the absence of ID deduplication also allow concurrent new records or deletions to shift pages. Append loads remain blocked while loading; replacement filter loads can now overlap, with requestId discarding stale responses/errors and only the latest request clearing loading. Category has no visible reset filters, so normal scrolling uses append mode only.

Sources: public/js/feed.js, controllers/articleController.js, public/js/api.js, controllers/pageController.js.

16. Empty category and footer

If initial articles are empty, EJS renders No articles found, explanatory canonical category text, and Return to Home. There is no feedCategory/grid/status/sentinel; feed.js exits, so newly published articles appear only after reload/navigation. Public footer is static publication/course/demo copy without interactive widgets.

Sources: views/pages/public/category.ejs, public/js/feed.js, views/partials/public/footer.ejs, controllers/pageController.js.

17. No JavaScript and verification

Without JavaScript the first 20 cards, count, descriptions, navigation, search GET, and native mobile menu work. Additional cards never load and logout type=button does nothing.
