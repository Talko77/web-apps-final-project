Component / architecture

1. How an error document is reached

This is a shared view, not a dedicated /error route. After page and API routers, server.js mounts notFound and errorHandler. An unmatched path or controller next() without a matching continuation reaches notFound. asyncHandler forwards rejected handlers to errorHandler. Role denial can render this view directly from auth middleware. The former /editorial and /technology redirect aliases were removed; those paths now reach notFound rather than home/category redirects. /login, /editor and /reporter convenience routes remain active.

Sources: server.js, middleware/errorHandler.js, utils/asyncHandler.js, middleware/auth.js, routes/pages.js.

Component / architecture

2. HTML versus API JSON

wantsJson is true for originalUrl starting /api/, req.xhr, or Accept containing application/json. These callers receive status plus {error:message}, never this HTML view. Unknown resources use 404 and The requested resource was not found. Browser api.js throws JSON error text; the owner page decides its DOM feedback. Ordinary HTML navigation receives the error document, except HTML authentication denials redirect to login. wantsJson is now exported by errorHandler.js and imported by auth.js, replacing its duplicate helper so centralized failures and direct denials use the same URL/XHR/Accept rules. This is a substring check rather than weighted Accept negotiation; /api/ always selects JSON even with Accept: text/html.

// Illustrative unmatched API path
HTTP 404
{"error":"The requested resource was not found"}

Sources: middleware/errorHandler.js, middleware/auth.js, public/js/api.js.

Component / architecture

3. Page Not Found card

notFound renders statusCode=404, statusMessage=Dispatch Missing, pageTitle=Page Not Found — The Daily Web, title=404 - Page Not Found, and the missing-story/desk message. Only numeric statusCode===404 selects the special kicker, Page Not Found heading, description, and three recovery links. Falsy/missing statusMessage falls back to Dispatch Missing; falsy/missing message falls back to the template’s missing-story/edition/workspace text. It performs no database query itself and changes no records.

Sources: middleware/errorHandler.js, views/error.ejs.

4. Generic error card and status mapping

CastError always responds 400 with Invalid identifier JSON or Bad Request HTML and a fixed identifier message. Otherwise status is err.status, or 400 for ValidationError, or 500. Errors at 500+ are logged and receive a generic message; lower-status errors expose err.message. Generic HTML locals omit statusCode, so even err.status=404 uses the generic card rather than the special missing-page branch.

Role denial renders Access Denied at 403 for HTML. requireRole uses the session account ID to re-read User.findById(...).select('role').lean() on every protected request. Missing sessions receive 401; deleted accounts trigger session.destroy and 401 with Your account no longer exists; disallowed database roles receive 403. On successful authorization the current database role is copied into the session. A database lookup rejection is forwarded by asyncHandler to centralized errorHandler. Missing authentication redirects HTML to /staff/login?next=encodedOriginalUrl; it does not render a 401 card. API denial instead returns 401/403 JSON. No stack trace is rendered by this template. The generic card tests whether title/message are defined, not whether they are truthy: omitted values fall back to Error and Something went wrong on our end., while supplied empty strings remain empty. HTTP status alone does not choose the 404 branch.

Sources: middleware/errorHandler.js, middleware/auth.js, views/error.ejs, utils/logger.js.

Component / architecture

5. HTML shell and asset loading

The complete error.ejs document includes shared/head, public/header-standard, the error card, and public/footer. Head loads /css/style.css and deferred /js/api.js. The public header is used even for staff errors, with showBreaking=false and empty searchQuery. There is no error-owned script, weather call, feed fetch, analytics increment, or database read in the view. The card has a 640px inline maximum width and uses shared utility spacing/surfaces plus page-shell centering and gutters; header/footer styling remains shared. The six CSS imports remain variables, base, utilities, components, layouts, then pages.

Sources: views/error.ejs, views/partials/shared/head.ejs, views/partials/public/header-standard.ejs, views/partials/public/footer.ejs, public/js/api.js, server.js, public/css/style.css, public/css/utilities.css, public/css/layouts.css.

Component / architecture

6. Header logo and public navigation

Logo and Home navigate to /; Search navigates to /search. Session currentUser selects Newsroom → Editor queue or Reporter dashboard plus Sign Out; guests receive Staff Login. These anchors make full document requests and invoke destination route authorization. Rendering the error view does not remove the session; deleted-account denial explicitly destroys it before responding. The public header reads res.locals.currentUser captured from the session before routing. A denied role is not refreshed in the session, so a 403 header may still show the old role’s Newsroom link; the destination performs its own fresh authorization.

Sources: views/partials/public/header-standard.ejs, server.js, routes/pages.js.

Component / architecture

7. Header search form

The header has a native GET /search form with input name=q and empty initial value. Submitting requests /search?q=encodedInput and loads the search page. No error-page JavaScript intercepts it, so it works without JavaScript. Header search does not retry the failed request.

Sources: views/partials/public/header-standard.ejs, controllers/pageController.js, routes/pages.js.

Component / architecture

8. Mobile navigation disclosure

Below 1024px, pages.css hides the standard header navigation/actions and shows the mobile disclosure; a native details/summary menu exposes Home, Search, and Staff Login. Opening it changes only the disclosure state; no API runs. Its login anchor remains static even when the desktop session-aware controls show Newsroom. Keyboard disclosure and links use native browser behavior.

Sources: views/partials/public/header-standard.ejs, public/css/components.css, public/css/pages.css.

Component / architecture

9. Card recovery links

The special 404 branch offers Return to Front Page → /, Search the Publication → /search, and Staff Login → /staff/login. Other errors offer only Back to Home → /. Icons are aria-hidden and text labels describe the action. Links do not call history.back, reconstruct an article, preserve the failed route as next, or retry its operation.

Sources: views/error.ejs, routes/pages.js.

Component / architecture

10. Sign Out from an error page

Shared api.js delegates logoutBtn clicks, disables the button, POSTs /api/auth/logout with same-origin credentials, then navigates to response.redirect or /. The controller destroys the session and clears connect.sid. Failure restores the button silently. This action is available only when the header rendered a signed-in user; no error-card status message handles logout failures.

Sources: public/js/api.js, controllers/authController.js, views/partials/public/header-standard.ejs.

Component / architecture

11. Footer, safety, and no-JavaScript behavior

The footer is static publication/course/demo-data text with no interactive component or API. Messages and titles use escaped EJS so user-influenced error strings are text, not HTML. Without JavaScript the error copy, search, recovery anchors, and details menu still work; Sign Out requires its script. A server error view does not prove the database or external services are operational.

Sources: views/error.ejs, views/partials/public/footer.ejs, public/js/api.js.
