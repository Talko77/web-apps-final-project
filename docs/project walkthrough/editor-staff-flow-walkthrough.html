1. Enter /editor/staff

The page route requires a session identity and the current database role Editor. requireRole looks up User.findById(sessionUser._id).select('role').lean() before the controller. Missing sessions are denied; a deleted account triggers session destruction and 401 denial. Only a permitted role is copied back into req.session.user.role. Guests requesting HTML redirect to /staff/login?next=%2Feditor%2Fstaff; Reporters get 403. All /api/users methods independently require Editor: guests receive JSON 401 and wrong roles JSON 403. Browser controls never grant permissions.

Sources: server.js, routes/pages.js, routes/users.js, middleware/auth.js, controllers/pageController.js, models/User.js, middleware/errorHandler.js.

2. Initial HTML and account list

staffDirectory reads User.find({}).sort({role:1,username:1}) with no limit, maps toPublic plus string IDs, and provides current session ID and [Reporter, Editor]. toPublic excludes the password and substitutes username for an empty displayName. EJS renders the full form and table before JavaScript. There is no initial /api/users fetch.

Sources: controllers/pageController.js, views/pages/editor/staff.ejs, models/User.js.

3. Assets and page startup

Shared head loads /css/style.css and deferred /js/api.js; deferred /js/staffDirectory.js follows at page end. The directory script reads staffTableBody data-current-user-id/data-roles, then attaches create, search, and delegated table handlers. CSS imports variables, base, utilities, components, layouts, pages in order. No weather, polling, article views, or initial account API occurs. Page-owned .staff-directory__* rules in pages.css account for the fixed header, wrap the create form with a 180px field flex basis, and keep the 880px-minimum table inside a horizontal scroll container. Below 640px fields and Create use full width and card/gutter spacing narrows. Shared header/control rules and base focus, disabled, and reduced-motion behavior still apply.

Sources: views/pages/editor/staff.ejs, views/partials/shared/head.ejs, public/css/style.css, public/js/staffDirectory.js, public/js/api.js, server.js, public/css/pages.css, public/css/base.css.

4. Newsroom header and sign out

Editor links open review queue, analytics, staff directory, or public homepage through full-page GETs. Identity comes from session locals. Sign Out disables logoutBtn and POSTs /api/auth/logout; success destroys the session, clears connect.sid, and navigates to redirect or /. Failure silently restores the button. Unsaved form/row edits are not preserved on navigation.

Sources: views/partials/newsroom/header.ejs, public/js/api.js, controllers/authController.js, server.js.

5. Intro and footer

The heading and explanation describe account management and one-way password hashes. The page-owned footer reads The Daily Web · Newsroom · Editor’s Desk. These are static EJS text with no API calls or live updates.

Sources: views/pages/editor/staff.ejs.

6. New username and display name

Create username is required with native minlength 3/maxlength 30; display name is optional with maxlength 60. Typing is local. Submit trims both; server validates username length and trims/truncates displayName to 60. Unique username violations return 400 That username is already taken. No availability probe is made.

Sources: views/pages/editor/staff.ejs, public/js/staffDirectory.js, controllers/userController.js, models/User.js.

7. New password and role

Password is required with native minlength 6 and type=password; submission preserves whitespace. Role select contains Reporter and Editor, defaulting to Reporter by option order. Server requires a valid configured role and at least six password characters. User.create triggers pre-save bcrypt.hash(password,10); responses never include plaintext or hash.

Sources: views/pages/editor/staff.ejs, public/js/staffDirectory.js, controllers/userController.js, models/User.js, config/constants.js.

8. Create account submission

Submit prevents navigation and disables only Create. POST /api/users sends {username,displayName,password,role}. HTTP 201 returns {success:true,user:{_id,username,displayName,role}}. On success the form resets and search clears, then GET /api/users?search= reloads the whole table, then flashes Created NAME. Finally Create re-enables. Fields and row actions remain editable while awaiting.

Sources: public/js/staffDirectory.js, views/pages/editor/staff.ejs, controllers/userController.js, routes/users.js, public/js/api.js.

9. Search input and list API

Input waits 250 ms after the last keystroke, trims search, and GETs /api/users?search=ENCODED. Server uses the shared escapeRegex imported from utils/queries.js, replacing the controller’s former local copy. It escapes regex metacharacters and performs case-insensitive substring matches on username OR displayName, sorts role/username, and limits to 200. Response is {users:[public user objects]}; render replaces tbody and toggles the empty message. No pagination or total is returned; initial HTML may have more rows than any reload.

Sources: public/js/staffDirectory.js, controllers/userController.js, models/User.js, utils/queries.js, views/pages/editor/staff.ejs.

10. Editable table rows

Server EJS escapes row values; client rowHtml uses api.escapeHtml and configured roles to rebuild the same controls. Username has maxlength 30, display name 60, role select, and optional new-password input. Typing sends nothing. Rows are not forms, so Save does not trigger native required/minlength validity checks. Server is responsible for validation.

Sources: views/pages/editor/staff.ejs, public/js/staffDirectory.js, public/js/api.js.

11. Save account and replace password

Save disables only its clicked button and PUTs /api/users/ID with all four fields. Username/displayName are trimmed; password remains raw. Empty password keeps existing hash; nonempty shorter than six returns 400, otherwise user.save() runs the modified-password hook and bcryptjs hashes it at cost 10. The controller deliberately uses document save rather than a query update so hashing runs; unchanged passwords are not rehashed. Server returns {success:true,user:publicObject}. Browser clears that row’s password and flashes Saved NAME, but does not re-render normalized values, sort/filter rows, or update header/session identity.

Sources: public/js/staffDirectory.js, controllers/userController.js, models/User.js, views/pages/editor/staff.ejs.

12. Role changes and session limits

Demoting an Editor counts Editors; count <=1 returns 409 This is the last editor and cannot be demoted. Saving your own account is allowed, including demotion when another Editor exists. The CRUD controller does not update sessions during that successful PUT, and the browser shows Saved without reloading. On the next protected request, middleware reads the database role again: a newly demoted Reporter is denied editor pages/APIs (HTML 403/JSON 403), so the old session role cannot retain editor authority. A permitted Reporter/staff request copies the new role into the session; an editor-only denial happens before that copy, so presentation snapshots can still show the old role until a permitted request or fresh sign-in. A promoted Editor likewise gains editor permission on the next relevant protected request. Username/displayName changes are not refreshed by role middleware, and password replacement does not terminate existing sessions. Deleted accounts are denied and their requesting session is destroyed at their next protected request (HTML login redirect/JSON 401). Public routes and /api/auth/me do not perform this role lookup. Count then save/delete is not an atomic transaction; concurrent last-editor changes are not serialized.

Sources: controllers/userController.js, middleware/auth.js, controllers/authController.js, server.js.

13. Delete account

Delete on your own row is disabled in both render paths. Other Delete buttons show native confirm: Delete the account "NAME"? This cannot be undone. Cancel sends nothing. Confirm disables the button, DELETEs /api/users/ID without a body, then reloads the current search and flashes Deleted NAME. Server independently rejects self-deletion and last-Editor deletion with 409, missing user with 404, otherwise awaits user.deleteOne and returns {success:true}. It does not delete authored articles or proactively enumerate/revoke sessions. At the deleted account’s next protected request, authorization finds no User, destroys that requesting session, and denies it. Existing articles remain; populated author display elsewhere falls back to Unknown through viewMappers.reporterName.

Sources: public/js/staffDirectory.js, controllers/userController.js, views/pages/editor/staff.ejs, routes/users.js, middleware/auth.js, utils/viewMappers.js.

14. Feedback, empty states, and overlapping operations

staffStatus uses role=status/aria-live=polite; api.flash uses safe textContent, unhides it, and toggles error/success classes without a timer. Initial empty-message markup is always hidden, even when server users are empty; client render shows it after an empty reload. No loading indicator exists for search. Errors leave old rows. No request IDs, abort controller, global saving guard, or disabled search exists: out-of-order searches can replace newer results. Create/delete can succeed but their follow-up reload fail, showing an error after the actual mutation.

Sources: public/js/staffDirectory.js, views/pages/editor/staff.ejs, public/js/api.js.

15. No JavaScript and verification

Without JavaScript, server rows and navigation remain visible, but search and row Save/Delete do nothing. Create form has no action/method, so valid native submission defaults to GET current URL with named fields—including password—in its query string; it does not create an account. This is documented behavior, not a recommended fallback. This update was checked by static source review and link validation. No template/browser execution, intercepted API, mocked controller, or database integration test was run. Persistence, hashing execution, session destruction, uniqueness races, and concurrent last-editor writes remain runtime checks.

Sources: views/pages/editor/staff.ejs, public/js/staffDirectory.js, controllers/userController.js, models/User.js.
