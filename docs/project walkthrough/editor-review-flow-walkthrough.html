Component / architecture

1. Open an article for review

The route is /editor/reviews/:id, opened through a queue headline or Review link. isEditor runs first: guest HTML requests go to login with next; Reporters receive 403. Its requireRole middleware reads User.findById(sessionUser._id).select('role').lean() on every protected request. An allowed database role is copied into the session; only role is refreshed, while displayName/username remain session values. A deleted account triggers session destruction and a 401 denial (login redirect for HTML, JSON for APIs). A changed role immediately governs the next protected request. editorReview reads Article.findById(id), populates reporter username/displayName, and uses lean. Editors are not restricted to their own articles.

Missing records fall through to 404; malformed IDs reach the centralized error handler. The route does not require pending status to render: draft, returned, or published records can also be opened, with decision controls disabled unless pending.

Sources: routes/pages.js, middleware/auth.js, models/User.js, controllers/pageController.js, middleware/errorHandler.js.

Component / architecture

2. View mapping and initial HTML

The controller maps publishedVersion and draftVersion into panes. Each includes title fallback, summary, category fallback, image URL/alt, raw content, and blank-line-split paragraphs. It maps status, reporter, category, updatedAt labels, views, editorNote, publication-count versions, and publication date. Categories are supplied only under page.categories; the duplicate top-level categories local and page.article.desk have been removed.

The full document includes shared head and newsroom header, review heading/notices, version strip, live pane, editable draft pane, and decision sidebar. It has no page footer. Shared head loads style.css and deferred api.js; deferred editorReview.js is last. No initial article API request, weather fetch, polling, or view increment occurs on this review route.

Styling follows the single style.css cascade: variables → base → utilities → components → layouts → pages. In pages.css, .review-article__main accounts for the fixed header; panes stack below 768px and become two columns at 768px. At 1024px the outer grid places comparison in 8 columns and decisions in 4. Shared header/control styling and base focus, disabled, and reduced-motion rules still apply.

Sources: controllers/pageController.js, views/pages/editor/review-article.ejs, views/partials/shared/head.ejs, views/partials/newsroom/header.ejs, public/js/editorReview.js, public/js/api.js, public/css/style.css, public/css/pages.css, public/css/base.css.

Component / architecture

3. Newsroom header and navigation

The session-derived Editor header has logo/Review Queue → /editor/reviews, Analytics → /editor/analytics, Staff → /editor/staff, View Public Site → /, identity, and Sign Out. Ordinary anchors navigate to new documents; they do not save draft edits before leaving.

This script has no autosave, dirty-state tracker, beforeunload warning, or visibility-change save. Unsaved draft edits remain browser-local and are lost on navigation/reload. Header branches are presentation; server route checks enforce permission.

Sources: views/partials/newsroom/header.ejs, server.js, routes/pages.js, public/js/editorReview.js.

Component / architecture

4. Review title and update notice

isUpdate is true only when isPublished is true and status is pending. It selects Article Update Review, the comparison instruction, and the notice that approved content stays public. Other states show Article Review even if a published version exists.

The browser tab title is Review: followed by draft title, else published title, else Article. These labels and notices are server snapshots and are not refreshed by saving edits. Saving an initially published article now changes its stored status to pending, but the current document retains Article Review and lacks the update notice until reload.

Sources: controllers/pageController.js, views/pages/editor/review-article.ejs, public/js/editorReview.js.

Component / architecture

5. Latest Editor Note

If the saved editorNote is nonempty, EJS displays a Latest Editor Note block using escaped text. It is separate from the editable Note to the reporter textarea, which always starts blank. The existing note is not prefilled there.

Saving draft content does not clear the saved note. Approval clears it; Request Changes replaces it. Those decisions navigate away, so this block is not locally updated.

Sources: controllers/pageController.js, views/pages/editor/review-article.ejs, controllers/articleController.js.

Component / architecture

6. Version and article metadata strip

Live version uses publishEvents.length, with v1.0 fallback for an isPublished record with no events. For never-published records the template still displays a v1.0 tag alongside Not published. Proposed version is v(approved+1).0 when isPublished, otherwise v1.0. These are publication-count labels, not edit counters.

Published date uses publishedAt or first publish event. Submitted uses updatedAt rather than a distinct submit timestamp. Public view increments now set timestamps:false, so reading the live story does not advance that edit/submission label. Both Desk and Category now read page.article.category, preferring draft.category then published.category then Uncategorised; Desk is a label for the same content metadata. Reporter name is obtained through shared utils/viewMappers.reporterName(article): populated displayName or username, else Unknown when the account has been deleted. Current views formats totalViews.

All these labels stay static after draft PUT. There is no relative-date timer or analytics refresh. statusClass/initials/pane labels are mapped but not all are consumed by this template.

Sources: controllers/pageController.js, utils/viewMappers.js, views/pages/editor/review-article.ejs, models/Article.js.

Component / architecture

7. Currently Live pane

If publishedVersion is null, the pane explains that there is no public version and shows 0 views. Otherwise it renders category, title, optional image, optional summary, and escaped paragraphs split on blank lines. It is read-only.

Image URLs trigger ordinary browser image requests and have no lazy or error-fallback handler. The pane is the database snapshot at page load; saving the draft does not change it. The review page itself does not count as a public article view.

Sources: controllers/pageController.js, views/pages/editor/review-article.ejs, public/js/editorReview.js.

Component / architecture

8. Proposed pane and editable content

The draft pane uses draftVersion || {}, so under normal controller mapping it exists even for an empty draft; the template’s no-draft fallback is not reached by that empty object. Title is mapped to (Untitled article) when blank and category to Uncategorised; the latter has no matching configured option, so the selector generally falls back to its empty placeholder.

The form appears on nonpending records too. It lets Editors save corrections without the Reporter pending lock. There is no computed diff, highlighted changed text, rich-text editor, autosave, counter, or side-by-side scroll synchronization in this script.

Sources: controllers/pageController.js, views/pages/editor/review-article.ejs, public/js/editorReview.js.

Component / architecture

13. Draft lead image URL and preview

The optional editorDraftImageUrl control is type=url. Save my edits is a native submit button, so an invalid nonempty URL can block form submission through browser constraint validation before the listener runs. No required fields are declared.

The server itself only stores an image URL string without URL/image validation. Existing preview img is rendered only at page load. Changing/clearing/saving a URL does not change its src or create a missing preview. Alt text remains the initial mapped draft title. No upload endpoint or draft-specific preview renderer is called.

Sources: views/pages/editor/review-article.ejs, public/js/editorReview.js, controllers/articleController.js, controllers/pageController.js.

Component / architecture

14. Save my edits and draft feedback

editorDraftForm submit prevents native navigation, disables only btn-save-draft-edits, and sends PUT /api/articles/ID with title, summary, content, category, imageUrl. It does not disable fields or decision buttons. Success flashes “Your edits are saved to the pending version.” in editorDraftStatus; failure flashes err.message; finally re-enables Save.

The success wording is used even if the opened article was not pending. The response’s status/savedAt fields are ignored. No reload, field normalization, metadata refresh, live-pane update, or navigation follows a draft save. In particular, an Editor save on initially published work now makes the database status pending, but the approval/return buttons remain disabled because their initial canDecide=false markup is unchanged. Reloading the review page enables decisions for the newly pending update.

// Illustrative correction
PUT /api/articles/507f1f77bcf86cd799439011
{"title":"Corrected headline","summary":"Summary","content":"Body",
 "category":"Science","imageUrl":""}

// HTTP 200
{"success":true,"articleId":"507f1f77bcf86cd799439011",
 "status":"pending","savedAt":"2026-10-06T08:00:00.000Z"}

Sources: views/pages/editor/review-article.ejs, public/js/editorReview.js, public/js/api.js, routes/articles.js, controllers/articleController.js.

Component / architecture

15. Server rules for Editor corrections

saveDraft finds the record, returns 404 if missing, and applies ownership/pending restrictions only to Reporters. An Editor can save any article, including pending. It replaces draftVersion with sanitized content; pending stays pending, returned stays returned, draft stays draft, and published becomes pending for an Editor so the edited version can be approved. A Reporter save on published work becomes draft instead. Approved public content stays live in both cases.

It awaits article.save before JSON success. It does not require complete content at save time. isDraftComplete() remains the submission check; the unused Article.hasPendingUpdate() method has been removed. The review controller computes isUpdate directly from isPublished and pending status. The editor decision branch also does not call isDraftComplete before publishing, so an Editor can save an incomplete pending draft and approve it. Reporter submission completeness is not reapplied here.

Sources: routes/articles.js, controllers/articleController.js, models/Article.js.

Component / architecture

16. Note to the reporter

editorNotes is a blank textarea separate from stored Latest Editor Note. Typing is local and never autosaved. Request Changes trims it and requires nonempty text in the browser, displaying “Add a note explaining what changes are needed.” and focusing it without an API request when empty.

The UI says a note is optional when approving, but Approve does not send editorNotes at all; typed approval notes are discarded and the server clears stored editorNote. Return truncates the supplied note to 1000 characters server-side. The textarea has no maxlength. The server independently converts the note to a string, trims it, rejects an empty result with HTTP 400 (Add a note explaining what changes are needed), then stores the first 1000 characters. Direct Editor API calls therefore cannot bypass the required-note rule.

Sources: views/pages/editor/review-article.ejs, public/js/editorReview.js, controllers/articleController.js.

Component / architecture

17. Approve & Publish

Enabled only for initial pending status. Click disables the clicked button and sends PATCH /api/articles/ID/status with {newStatus:"published"}. PATCH is now the only status route; the previous POST alias was removed. There is no confirmation or automatic PUT. Approval publishes the saved database draft, so unsaved field edits are not part of this request.

The server requires current pending status, copies draftVersion into publishedVersion, sets status=published and isPublished=true, preserves an existing publishedAt or assigns now for first publication, appends a new publishEvents timestamp, and clears editorNote. After await save it returns success/status/isPublished. The browser ignores fields and navigates to /editor/reviews.

PATCH /api/articles/507f1f77bcf86cd799439011/status
{"newStatus":"published"}

// HTTP 200
{"success":true,"status":"published","isPublished":true}

First approval makes the article public; update approval replaces approved content but keeps original publication time. This is read/validate/save without an explicit conditional status update or transaction.

Sources: public/js/editorReview.js, routes/articles.js, controllers/articleController.js, models/Article.js, controllers/pageController.js.

Component / architecture

18. Request Changes

After browser note validation, the clicked return button is disabled and PATCH sends newStatus=returned plus trimmed editorNote. Server requires pending status, trims and requires a nonempty note again, and caps it at 1000 characters before saving returned state/note. It preserves draftVersion, publishedVersion, isPublished, publishedAt, views, and publication events.

Success navigates to the queue. A Reporter can subsequently edit the returned draft and re-submit; an existing live version stays public. The page does not notify the reporter by email or push. Note display is driven by later dashboard/editor renders.

PATCH /api/articles/507f1f77bcf86cd799439011/status
{"newStatus":"returned","editorNote":"Verify the quoted source."}

// Example for an already-live story, HTTP 200
{"success":true,"status":"returned","isPublished":true}

Sources: public/js/editorReview.js, controllers/articleController.js, routes/articles.js, models/Article.js, views/pages/reporter/articles.ejs.

Component / architecture

19. Delete Article

Delete is available for every rendered status. A native confirm asks whether to permanently delete the article, comments, and view data. Cancel sends nothing. Confirm disables Delete and sends DELETE /api/articles/ID with no body. The route is Editor-only.

remove calls Article.findByIdAndDelete, returns 404 if absent, then awaits Comment.deleteMany and Analytics.deleteMany in parallel. It responds {success:true}; browser navigates to the queue. Cleanup is not a database transaction: an Article may already be removed if dependent cleanup fails. The browser then shows an error and re-enables Delete; a retry can return 404. No soft delete or undo is implemented.

Sources: public/js/editorReview.js, routes/articles.js, controllers/articleController.js, models/Comment.js, models/Analytics.js.

Component / architecture

20. Decision state, concurrency, and errors

canDecide comes from initial status===pending. Nonpending pages show an unavailable message and disabled approval/return controls; deletion and draft editing remain available. Server reads status again and rejects decisions on a record already outside pending at that read; this is not an atomic guard against simultaneous decisions. Saving initially published work changes stored status to pending, but editorReview.js does not update canDecide or enable the initially disabled buttons. Reload is needed to show the pending update and enable its decisions.

act disables only its clicked button. Other decisions and Save can run concurrently, and fields remain editable. There is no shared saving guard, queued workflow, conflict token, or abort controller. Save/approval races can publish an older stored draft or overwrite changes; source checks document the potential rather than claiming a live race test.

Failures flash text safely in statusAlert or editorDraftStatus. Decision failures enable the clicked button; Save restores its button in finally. No automatic retry, login redirect, refresh, or message-clearing timer exists. Relevant errors include 401 missing session/deleted account; 403 current database role or ownership rejection; 404 missing record; 400 invalid ID, illegal status, or blank return note; and generic 500. Each PUT/PATCH/DELETE rechecks the database role in middleware; an account changed from Editor to Reporter cannot retain unrestricted editing or deletion through a stale page. sendJSON uses same-origin credentials, JSON Content-Type, and browser-default Accept */* because its options replace the helper’s initial headers.

Sources: views/pages/editor/review-article.ejs, public/js/editorReview.js, public/js/api.js, middleware/auth.js, middleware/errorHandler.js, controllers/articleController.js.

Component / architecture

21. Public links and preview behavior

The live pane’s View on public site link opens /articles/ID in a new tab with noopener noreferrer. The draft pane’s Preview as it will appear uses the same public URL when publishedVersion exists; it shows current approved content, not the proposed or unsaved draft.

For never-published stories, that proposed preview anchor points to # and still has target=_blank; it does not call a dedicated preview renderer. Opening an actual public article triggers the public article-page view tracking, unlike this review page. This review script does not add any preview endpoint or local preview DOM.

Sources: views/pages/editor/review-article.ejs, public/js/editorReview.js, controllers/pageController.js.

Component / architecture

22. Sign Out and no-JavaScript behavior

Sign Out uses shared api.js to POST /api/auth/logout, destroy session, clear connect.sid, and navigate home. Failure silently restores the logout button; it does not save edits first.

Without JavaScript, initial comparison and links still work; approve/return/delete buttons do nothing. Save my edits is a native submit button on a form without action/method or named field controls, so ordinary submission is GET of the current route and does not call the draft PUT. Native URL validity still applies. No default POST fallback exists. Pending-only restrictions still run on the server for direct API calls.

Sources: views/pages/editor/review-article.ejs, public/js/editorReview.js, public/js/api.js, controllers/authController.js.

23. Verification and learning steps

Try an empty return note, a valid note, and canceling Delete. Observe unchanged metadata/preview after save and the queue document after a successful decision.
