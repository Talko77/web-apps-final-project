Component flow

1. Entering /editor/analytics

This is a redirect entry point, not a dashboard containing all articles. Editor middleware requires a session and re-reads the account’s current role from MongoDB before granting access. The controller finds the most-viewed published article, sorting totalViews descending, and redirects to its article analytics URL. No published article means next(), leading to the centralized not-found response; there is no analytics empty landing page.

Sources: controllers/pageController.js, routes/pages.js, middleware/auth.js, middleware/errorHandler.js.

Component flow

2. Direct article analytics route

/editor/articles/:id/analytics is Editor-only. Guests requesting HTML go to /staff/login?next=…; Reporters get 403. API guests receive JSON 401; incorrect roles receive 403. requireRole fetches User.findById(session.user._id).select('role').lean() for every protected page/API request. It denies a changed disallowed role with 403, destroys a deleted account’s session and denies with 401, and refreshes the session role on success. HTML 401 uses the login redirect; API 401 uses JSON. The role is not accepted from browser controls. The article lookup does not require isPublished, so a direct URL can render a draft. Missing records continue to 404; malformed ObjectIds reach centralized error handling.

Sources: controllers/pageController.js, routes/pages.js, server.js, middleware/auth.js, middleware/errorHandler.js.

Component flow

3. What loads into the HTML

The server chooses publishedVersion || draftVersion || {}, maps title/category/reporter, and reads all-time total views, seven-day bucket sum, publication history, and first publication time. The complete EJS document contains the shared head and newsroom header, summary, chart controls, an initially empty canvas, hidden status, legend, four metrics, and a page-owned footer. An image URL is mapped but not rendered. The initial HTML contains no timeline JSON.

Sources: controllers/pageController.js, routes/pages.js, views/pages/editor/analytics.ejs, views/partials/shared/head.ejs, public/css/style.css, utils/viewMappers.js.

Component flow

4. Newsroom navigation and sign out

The session identity determines Editor navigation: Review Queue, Analytics, Staff. The logo opens the queue and View Public Site opens /. These are ordinary document navigations. Sign Out uses delegated shared JavaScript, disables its button, POSTs /api/auth/logout, then follows the returned redirect or /. Failure re-enables the button without visible feedback. The server destroys the session and clears connect.sid.

Sources: views/partials/newsroom/header.ejs, views/partials/shared/site-logo.ejs, controllers/authController.js, public/js/api.js.

Component flow

5. Article title, category, reporter

The header is server-rendered from the initial article version. It does not change when the article dropdown changes. The browser fetch returns title but the script never consumes it. Consequently, the canvas can display one article while the heading and metrics still describe the originally loaded article.

Sources: controllers/pageController.js, routes/pages.js, views/pages/editor/analytics.ejs, public/js/analyticsChart.js.

Component flow

6. First chart request

After parsing, the script finds the canvas, obtains its 2D context, captures controls, installs listeners, and calls load(articleId(), range.value). Default range is now 504 hours (three weeks), from the selected EJS option. analyticsChart.js has no numeric default: if the range control is absent/empty, load omits hours and the API applies its 504-hour fallback. Article ID prefers the select value and falls back to the canvas dataset. There is no polling, automatic public view increment, or initial analytics-list API request.

Sources: public/js/analyticsChart.js, public/js/api.js, views/pages/editor/analytics.ejs, controllers/analyticsController.js, routes/analytics.js.

Component flow

7. Article dropdown and its 100-item limit

Server menu query selects only published articles, sorted by total views descending and capped at 100 through shared analyzableArticles() in utils/queries.js. This replaces the former 50-item server-rendered menu, matching the API’s 100-item cap. The query projects publishedVersion.title, totalViews and publishEvents and uses lean records; ties have no explicit secondary sort. It marks the requested ID selected only if present. A direct URL for an unpublished or lower-ranked article can therefore render that article’s heading while the browser defaults to the first menu article and fetches its timeline. An empty menu falls back to the canvas ID. Changing selection replaces the URL immediately with /editor/articles/ID/analytics, then fetches JSON without re-rendering the page.

No pushState, popstate handler, or abort is installed. ReplaceState does not create a separate history entry. The page-unused GET /api/analytics/articles uses the same analyzableArticles helper and returns up to 100 published candidates with _id/title/totalViews/updateCount; this page never calls it.

Sources: controllers/pageController.js, routes/pages.js, public/js/analyticsChart.js, views/pages/editor/analytics.ejs, controllers/analyticsController.js, routes/analytics.js, utils/queries.js.

Component flow

8. Time range selector

Choices are 48, 96, 168, and 504 (initial) hours. A change immediately calls load for the currently selected article; no debounce and no URL range parameter. Refresh therefore restores 504 hours. The four metrics remain unchanged even when the chart range changes.

Sources: public/js/analyticsChart.js, views/pages/editor/analytics.ejs, controllers/analyticsController.js, routes/analytics.js.

Component flow

9. Timeline API: query and response

Editor middleware precedes the controller. Parse hours using parseInt(value,10) || 504, then clamp between 6 and 720. Values such as 0 or nonnumeric become 504; negative values become 6. The start time is rounded down to the local hour. MongoDB reads ascending existing hourly buckets from that time, without a missing-hour fill or explicit upper-time bound. There is no aggregation or response pagination for this query.

// Illustrative response; not live data
GET /api/analytics/article/507f1f77bcf86cd799439011?hours=504
200 {
  "title": "Example headline", "totalViews": 120,
  "timeline": [{"timestamp":"2026-10-06T08:00:00Z","viewsCount":3}],
  "publishEvents": ["2026-10-05T10:00:00Z"]
}

Title is approved title or draft title. totalViews is cumulative, not a sum of the requested range. publishEvents is filtered to dates greater than or equal to the same start time. Missing article gives 404 JSON {error:"Article not found"}. The browser consumes timeline, publishEvents and totalViews; ignores title.

Sources: controllers/analyticsController.js, routes/analytics.js, models/Analytics.js, public/js/analyticsChart.js.

Component flow

10. Canvas plot, axes and line

The drawing uses plain Canvas, with no chart library. Device pixel ratio scales backing dimensions; CSS dimensions define drawing area. X coordinates span first to last returned timestamp, and Y uses max views or 1. Five horizontal gridlines and up to six localized time labels are drawn, followed by a shaded area and dark line. Missing buckets are connected directly, not treated as zero views. One point has zero time span corrected to 1, so it is positioned at the left edge.

This is a static chart: no hover tooltip, interactive zoom, download, accessible data table, or per-point DOM content. The canvas has role=img and a fixed aria-label; the adjacent status gives aggregate feedback.

Sources: public/js/analyticsChart.js, views/pages/editor/analytics.ejs.

Component flow

11. Publication markers and legend

The legend describes dark views and dashed red approval markers. Drawing considers filtered API events, skips events outside the actual first/last bucket times, and labels the first returned event Published, later ones Update 1, Update 2, etc. Because the API already filters publication history, a later update can be mislabeled Published after the initial publication falls outside the range. The status count max(0, filteredEvents.length - 1) can undercount updates and count events that were not drawn outside the bucket span.

Sources: controllers/analyticsController.js, routes/analytics.js, public/js/analyticsChart.js, views/pages/editor/analytics.ejs, controllers/articleController.js.

Component flow

12. Empty buckets and no JavaScript

An empty timeline draws “No view data for the selected time range” on the canvas, without axes or markers. Success status still prints cumulative total and filtered-event count. With scripts unavailable, server labels, menus and cards remain visible, but the canvas stays empty and range/reset controls have no behavior. Links still work. No server-rendered chart fallback exists.

Sources: public/js/analyticsChart.js, views/pages/editor/analytics.ejs.

Component flow

13. Loading, errors and repeated requests

#chartStatus is a polite live status. api.flash writes textContent, removes state-hidden, and toggles color-alert/color-muted; there is no automatic clearing timer. Loading does not clear the old chart or disable article/range controls. A rejected fetch or non-2xx response shows body.error or Request failed (status), while retaining previous current data. A 2xx non-JSON body becomes null and then throws when load reads timeline.

Requests have no abort signal or sequence guard. If two loads overlap, whichever response completes last paints last, even when it corresponds to an earlier selection. Controls, URL, chart and summary can therefore disagree. There is no automatic retry.

Sources: public/js/analyticsChart.js, public/js/api.js.

Component flow

14. Reset view data button

Clicking Reset view data asks native confirmation: “Delete all recorded view data for this article? The chart and the view count reset to zero and this cannot be undone.” Cancel makes no API request. Confirm disables only Reset, sends a bodyless DELETE for the selected article, awaits a load for the then-current selection/range, writes “View data reset for this article.”, and re-enables the button in finally.

Article and range can still change while DELETE is pending. The target is captured when DELETE is called but the follow-up load reads current controls again. Since load catches its own errors, a failed post-delete reload is overwritten by the reset-success message. Metrics and publication history are not refreshed.

Sources: public/js/analyticsChart.js, public/js/api.js, controllers/analyticsController.js, routes/analytics.js.

Component flow

15. Reset persistence and response

Editor-only reset first finds the article ID; missing record returns 404. It concurrently deletes its Analytics buckets and sets Article.totalViews to zero with Promise.all. It logs the acting session username and returns 200 {success:true, deletedBuckets:N}. The browser ignores these fields. The operations have no transaction: one can persist while the other fails. Concurrent public page requests can increment counters during reset, so a truly zero post-reset snapshot is not guaranteed.

Reset does not delete articles, comments, published/draft versions, publication events, or first-published date. It changes popularity ordering through totalViews. The 100-item menu already rendered is not re-sorted. Article.updateOne uses {timestamps:false}, preserving updatedAt so an analytics reset does not change newsroom queue ordering or the Reporter’s last-saved timestamp.

Sources: controllers/analyticsController.js, routes/analytics.js, models/Analytics.js, models/Article.js, middleware/auth.js.

Component flow

16. Total Views metric

Initial card value is formatViews(article.totalViews), with “Since publication”. This is a server snapshot of the cumulative field. Neither chart loads nor resets modify its DOM. Chart status separately uses the latest API total, so the card may disagree after resetting or switching articles.

Sources: controllers/pageController.js, routes/pages.js, views/pages/editor/analytics.ejs, utils/viewMappers.js.

Component flow

17. Views This Week metric

The controller aggregates Analytics buckets with timestamp at or after the rounded current time minus seven days, summing viewsCount into one total. No result means zero. “Last 7 days” is rolling time rounded down, not a calendar week. This query is independent of the default three-week chart range and runs before HTML rendering.

Sources: controllers/pageController.js, routes/pages.js, views/pages/editor/analytics.ejs, models/Analytics.js, utils/viewMappers.js.

Component flow

18. Approved Updates metric

Server card uses all article publishEvents: max(0, events.length - 1), counting approvals after initial publication. It is independent of isPublished/status and chart filtering. The first approval adds a publication event, and later publication approvals append events. Resetting views keeps events. Chart status uses only API-filtered history, so its update number can be smaller.

Sources: controllers/pageController.js, routes/pages.js, views/pages/editor/analytics.ejs, controllers/articleController.js.

Component flow

19. First Published metric

The card uses publishedAt: formatRelative for the value and formatDateTime for the comparison. The first publication assigns a date; subsequent approvals retain that date. This is not the latest update time. Missing publication date uses formatter fallback. Browser range changes do not change either label.

Sources: controllers/pageController.js, routes/pages.js, views/pages/editor/analytics.ejs, controllers/articleController.js, utils/viewMappers.js.

Component flow

20. Resize handling and page footer

Resize events debounce drawing by 150ms and redraw current data at new canvas dimensions; no API request is made. The page-owned footer says “The Daily Web · Newsroom · Editor’s Desk” and has no interactive controls. It does not include the public footer or weather widget. pages.css owns the analytics shell, controls and chart frame: metrics stack below 640px and use two columns from 640px, when the chart header also becomes a row. The editor-analytics-page modifier fixes the plot height using --analytics-chart-height; redraw fits that CSS size.

Sources: public/js/analyticsChart.js, views/pages/editor/analytics.ejs, public/css/pages.css, public/css/variables.css.

Component flow

21. Where view data originates

Public GET /articles/:id schedules two atomic increments without awaiting them: Analytics.updateOne for the rounded hour with upsert/$inc, and Article.updateOne totalViews/$inc with {timestamps:false}. A public reading visit therefore does not advance updatedAt or reorder the newsroom by edit time. Analytics has a unique article/timestamp index. Each successful public rendering schedules counting again; session seen-history does not suppress repeated increments. These two writes are not a single transaction. Failures are logged without failing article rendering. Analytics-page navigation and JSON reads do not increment views.

Sources: controllers/pageController.js, models/Analytics.js, models/Article.js.
