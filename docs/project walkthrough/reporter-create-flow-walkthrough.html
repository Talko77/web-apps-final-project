Component / architecture

1. Open New Article

The route is /reporter/articles/new/edit, reached from My Articles or the newsroom header. isReporter runs before reporterEdit. Guests go to /staff/login?next=...; an Editor receives 403. requireRole reads the signed-in user’s current role from User.findById(sessionUser._id).select('role').lean() on every protected request. A deleted account triggers session destruction and a 401 denial (login redirect for HTML, JSON for APIs); an allowed role is copied back into the session. Only the role is refreshed, so displayName/username still come from the session. The controller recognizes the new route and does not query or create an Article record.

Sources: server.js, routes/pages.js, middleware/auth.js, models/User.js, controllers/pageController.js, views/pages/reporter/edit-article.ejs.

Component / architecture

2. Initial locals and HTML composition

reporterEdit supplies pageTitle=New Article, newsroomRole=Reporter, and article locals: id="", isNew=true, status=draft, statusLabel=Draft, locked=false, isPublished=false, liveVersion=Not yet published, draftVersion=v1.0 Draft, savedAt=Not saved yet. Title, summary (named subtitle in the view model), body, image, category, and notes start blank; author comes from session displayName or username. Categories come from config.

The complete document includes shared head, newsroom header, breadcrumb, five field controls, revision ledger, action buttons, feedback, and its own footer. No list, authoring-data, weather, or identity JSON fetch occurs at startup.

Sources: controllers/pageController.js, views/pages/reporter/edit-article.ejs, config/constants.js, views/partials/shared/head.ejs, views/partials/newsroom/header.ejs.

Component / architecture

3. Scripts and browser state

Shared head loads /css/style.css and deferred /js/api.js; the page ends with deferred /js/article-editor.js. api.js runs first. The editor script captures fields, save/submit buttons, feedback, counter, articleId, and a fixed locked flag. It snapshots initial field values into lastPersisted so untouched blank pages do not autosave.

Browser state is an in-memory serialized snapshot, not localStorage. Saving uses a saving guard; autosave uses a timer. The document has no rich-text framework. public/css/style.css imports variables → base → utilities → components → layouts → pages. Shared newsroom-main, reporter-workspace, and newsroom-footer rules in layouts.css own the header offset, workspace, and footer. Page-owned .article-editor__* rules in pages.css give the form a single column below 1024px and a 12-column grid (main 8/sidebar 4) at 1024px. The image preview changes from stacked to horizontal at 640px; common focus, disabled, and reduced-motion rules remain in base.css.

Sources: views/pages/reporter/edit-article.ejs, public/js/article-editor.js, public/js/api.js, public/css/style.css, public/css/layouts.css, public/css/pages.css, public/css/base.css.

Component / architecture

4. Header, breadcrumb, and leaving the page

The Reporter header offers My Articles, New Article, View Public Site, and Sign Out. The logo and My Articles breadcrumb navigate to the reporter dashboard. Links request separate HTML pages; they do not explicitly save first. New Article opens another blank editor rather than reusing the current draft.

There is no beforeunload confirmation or awaited navigation-save step. The visibilitychange handler tries to save when the document becomes hidden, but normal fetch has no keepalive/beacon guarantee during navigation or tab closing. Leaving before the debounce has run can lose changes if the request does not complete.

Sources: views/partials/newsroom/header.ejs, views/pages/reporter/edit-article.ejs, public/js/article-editor.js, routes/pages.js.

Component / architecture

5. Headline field

#articleTitle is a required text input with maxlength=200. Typing updates only the field and schedules autosave. collect maps it to payload.title without trimming in the browser. The server slices to 200 characters; the Mongoose field also trims. Save Draft accepts an empty headline, while Submit checks its trimmed value.

Sources: views/pages/reporter/edit-article.ejs, public/js/article-editor.js, controllers/articleController.js, models/Article.js.

Component / architecture

6. Summary and remaining-character counter

#articleSubtitle is a required textarea with maxlength=500. collect calls this field summary. The counter runs at startup and on input, showing 500 minus value.length characters remaining. It is a browser string-length counter, not a word or database count. input also schedules autosave.

The server truncates summary to 500 and the schema trims it. Neither the counter nor typing alone sends an API request.

Sources: views/pages/reporter/edit-article.ejs, public/js/article-editor.js, controllers/articleController.js, models/Article.js.

Component / architecture

7. Optional lead image URL and preview

#articleImageUrl is type=url but is optional. Save/Submit buttons are type=button and do not call reportValidity/checkValidity, so native URL validity does not block these Ajax actions. The server converts imageUrl to a string without URL or image-ratio validation.

The new page has no preview element. An existing image is included as an img only during EJS rendering, with draft title as alt. Changing the URL, clearing it, or saving does not update or remove the current preview in the DOM. A reload renders the stored URL. The browser loads that image separately; there is no upload endpoint, file picker, proxy, or error fallback in this feature.

Sources: views/pages/reporter/edit-article.ejs, public/js/article-editor.js, controllers/articleController.js, controllers/pageController.js.

Component / architecture

8. Article body textarea

#articleBody is a required plain textarea with no explicit maxlength. collect maps it to content without browser trimming. The API converts it to a string; request parsing has a 1 MB body limit in server.js. There is no rich-text toolbar, live article preview, or body word counter here.

The hint explains blank-line paragraphs on the public page. Public rendering later splits approved content into escaped paragraphs; authoring does not publish or render HTML supplied in the body.

Sources: views/pages/reporter/edit-article.ejs, public/js/article-editor.js, controllers/articleController.js, server.js, controllers/pageController.js.

Component / architecture

9. Category selector

#articleCategory starts at Select a category with empty value and offers the seven configured categories. Selecting schedules autosave through input/change listeners. collect sends category; the server preserves only an allowed value, otherwise empty string.

Manual Save Draft accepts an empty category. Submit’s local completeness check requires a nonblank value; server isDraftComplete also requires category membership in CATEGORIES.

Sources: views/pages/reporter/edit-article.ejs, public/js/article-editor.js, controllers/articleController.js, models/Article.js, config/constants.js.

Component / architecture

10. Version Details and action status badges

The ledger shows Author, Status, Live version, Draft version, and Last saved. The action card repeats the status label. These are server-rendered snapshots: after a successful POST/PUT the script updates only articleId/URL and feedback, not ledger fields, breadcrumb, page title, or status badge.

A newly saved page can therefore still say New Article and Not saved yet until reload. PUT returns status and savedAt but the script ignores them. Publication-count version labels are not autosave revision numbers. Autosaved at uses the browser’s current time, not the server’s savedAt.

Sources: views/pages/reporter/edit-article.ejs, controllers/pageController.js, public/js/article-editor.js, utils/viewMappers.js.

Component / architecture

11. Save Draft button and shared persistence path

Clicking Save Draft clears the autosave timer and calls persist(false). It returns false immediately if already saving or locked. Otherwise it sets saving=true and disables both action buttons, snapshots all five fields, then creates or updates the draft. It permits partial and completely blank drafts and does not submit the form or trigger native required validation.

Success stores JSON.stringify(payload) as lastPersisted and shows Saved. Failure shows Save failed: MESSAGE. Finally resets saving and restores both buttons according to the initial locked flag. Fields remain editable throughout the request.

Sources: public/js/article-editor.js, views/pages/reporter/edit-article.ejs, public/js/api.js.

Component / architecture

12. First persistence creates the Article

Without an ID, persist sends POST /api/articles with the full collected payload. isReporter authorizes; create sets reporter from session, status=draft, and sanitized draftVersion. Article.create assigns model defaults, including isPublished=false and publishedVersion=null, and timestamps. No request role or owner is trusted.

// Illustrative partial draft
POST /api/articles
{"title":"Example headline","summary":"","content":"",
 "category":"Science","imageUrl":""}

// HTTP 201
{"success":true,"articleId":"507f1f77bcf86cd799439011"}

The browser consumes articleId, sets form.dataset.articleId, and history.replaceState to /reporter/articles/ID/edit without reloading. The next save uses PUT. The response does not contain the full draft or timestamps. If creation succeeds but its response is lost, the browser may still have no ID, so a retry can create another record; no idempotency key is implemented.

Sources: routes/articles.js, controllers/articleController.js, models/Article.js, public/js/article-editor.js.

Component / architecture

13. Saving an existing ID

Once articleId exists, persistence sends PUT /api/articles/:id with all five fields, replacing draftVersion rather than patching an individual field. isStaff runs first; saveDraft allows a Reporter only on their own article, rejects missing records with 404, and rejects pending Reporter edits with 409.

A published-status article becomes draft when a Reporter saves, while publishedVersion and isPublished remain. The same shared API lets an Editor save any article, including pending work; an Editor’s save of published-status work instead moves it to pending. This reporter page is still Reporter-only. Returned status remains returned. The save awaits article.save and responds with success, articleId, status, and savedAt. The browser ignores those fields on PUT and records its original payload as the snapshot, so server trimming/sanitization is not reflected in inputs.

// Illustrative PUT response, HTTP 200
{"success":true,"articleId":"507f1f77bcf86cd799439011",
 "status":"draft","savedAt":"2026-10-06T08:00:00.000Z"}

Sources: routes/articles.js, controllers/articleController.js, models/Article.js, public/js/article-editor.js.

Component / architecture

14. Five-second autosave

For each unlocked field, input and change clear the prior timer and set a new 5000-ms timer. When it fires, current JSON is compared with lastPersisted. Only changed data calls persist(true). An untouched new page creates nothing; editing even one field can create a partial Article.

Autosave uses the same POST/PUT path, but leaves action buttons enabled and shows Autosaved at HH:MM on success or Autosave failed: MESSAGE on failure. There is no periodic polling. A failed save is not automatically retried unless another event triggers persistence.

Sources: public/js/article-editor.js, public/js/api.js.

Component / architecture

15. Saving when the document becomes hidden

visibilitychange checks document.visibilityState===hidden and hasUnsavedChanges. It clears the pending timer and calls persist(true) immediately. Switching tabs can trigger this path. locked editors do not register this listener.

This is a normal asynchronous fetch, not sendBeacon or keepalive. It may not finish before a tab closes. If saving is already true, persist returns false; there is no queued retry for changes made during that request. The source comment promises preservation on closing, but actual delivery is not guaranteed.

Sources: public/js/article-editor.js, public/js/api.js.

Component / architecture

16. Submit for Review: local completeness

The submit button clears autosaveTimer and checks trimmed title, summary, content, and category in that order. The first missing value shows Add a headline/a summary/the article body/a category before submitting for review, focuses that field, and sends no request. Image is optional.

The handler uses its own validation, not form.reportValidity. A complete draft first awaits Save Draft, even if unchanged. If saving is already in flight, saveDraft returns false and the submit attempt stops; the button may appear enabled during autosave, but no queued submit follows.

Sources: public/js/article-editor.js, views/pages/reporter/edit-article.ejs, models/Article.js.

Component / architecture

17. Save first, then request pending status

After successful persistence and a nonempty ID, the script disables the submit button and sends PATCH /api/articles/ID/status with {newStatus:"pending"}. PATCH is the only status route; the former POST status alias has been removed. The middleware checks the current database role again, and the Reporter branch checks ownership, source status draft/returned, target pending, and isDraftComplete. It changes status to pending, clears editorNote, and saves. Approved public content remains intact.

// Status request after POST/PUT succeeded
PATCH /api/articles/507f1f77bcf86cd799439011/status
{"newStatus":"pending"}

// HTTP 200 for a new story
{"success":true,"status":"pending","isPublished":false}

Success navigates to /reporter/articles; it does not lock fields in the current DOM. PATCH failure shows the error and re-enables submit, leaving the saved draft and ID intact. This is two requests, not one transaction. Save Draft was re-enabled in persist’s finally before PATCH, so it can be clicked during the transition; fields also remain editable.

Sources: public/js/article-editor.js, routes/articles.js, controllers/articleController.js, models/Article.js.

Component / architecture

18. Changes made during a save

Each persistence captures one payload. If the reporter types while it is in flight, the inputs can become newer than that payload. Success records the original payload as lastPersisted, keeping newer input dirty. A newly scheduled timer may save it later, but if that timer fires while saving=true, its persistence attempt is skipped without rescheduling.

Submit validates before saving. Edits during the save are not collected again before PATCH, so submission may send the saved older draft rather than the newest visible fields. Status requests are outside the saving guard. There are no revision tokens or cross-tab conflict controls; another save can overwrite draftVersion.

Sources: public/js/article-editor.js, controllers/articleController.js.

Component / architecture

19. Existing drafts, locks, and editor notes

The new route has none of the conditional notices. After first creation its URL points to the existing editor route. A later GET queries by ID and Reporter ownership, renders draftVersion, and returns 404 for a missing/unowned record. Pending status sets locked=true, disables fields/actions, and displays Awaiting Editor. Server PUT also enforces the lock.

isPublished shows the public-version notice; editorNote shows escaped feedback and re-submit instructions. Approved events derive the version labels. Editors must now supply a trimmed, nonempty note when returning pending work; the server caps that note at 1000 characters. A returned article remains returned while being saved and becomes pending after re-submission, which clears the note. Notice/lock updates require another page render; the locked flag is not refreshed by the script.

Sources: controllers/pageController.js, views/pages/reporter/edit-article.ejs, public/js/article-editor.js, controllers/articleController.js, routes/pages.js.

Component / architecture

20. Feedback, errors, and retry

#articleActionMessage starts hidden with role=status and aria-live=polite. api.flash uses textContent and color classes; there is no automatic timer clearing. Manual/auto failures get Save failed: or Autosave failed: prefixes. Status failures show the server message directly. Fields and existing ID remain for retry.

Relevant API errors: 401 missing session or deleted account; 403 current database role not permitted or wrong owner; 404 missing article; 409 pending save lock; 400 invalid ID or incomplete/illegal status; unexpected errors generally 500. Request body too large is rejected by server parsing. JSON errors become thrown Errors; non-JSON failures fall back to Request failed (STATUS). No request timeout, automatic login redirect, offline queue, or automatic retry exists.

sendJSON uses same-origin credentials and JSON Content-Type. Because its options object overwrites the helper’s constructed headers, POST/PUT/PATCH use browser-default Accept */*. The /api routes still return JSON errors by URL.

Sources: public/js/article-editor.js, public/js/api.js, routes/articles.js, controllers/articleController.js, middleware/auth.js, middleware/errorHandler.js, server.js.

Component / architecture

21. Sign Out, footer, and no-JavaScript fallback

Sign Out uses the shared POST /api/auth/logout handler, destroys session, clears connect.sid, and navigates home. Failure silently restores its button. It does not await a draft save before logout. The page-owned footer is static Internal Newsroom System text.

Without JavaScript, server content and ordinary links work, but Save Draft/Submit buttons (type=button) do nothing, autosave/counter do not run, and Sign Out does nothing. There is no native POST fallback. The form has no submit interception, action, or method; if a native form submission is triggered, browser defaults apply rather than the authoring APIs. On this multi-control form, ordinary Enter behavior is browser/form dependent; no save handler is attached to form submit.

Sources: views/pages/reporter/edit-article.ejs, public/js/article-editor.js, public/js/api.js, controllers/authController.js, views/partials/newsroom/header.ejs.

22. Verification and learning steps

Using safe local data, open New Article and confirm no creation request. Type one field and wait five seconds for POST; note the ID and URL replacement. Change another field and save for PUT. Compare the counter, unchanged metadata/preview, and feedback. Complete required fields, then inspect the save followed by status PATCH and dashboard navigation.
