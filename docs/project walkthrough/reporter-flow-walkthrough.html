Route and authorization

1. Entering the reporter dashboard

The dashboard URL is /reporter/articles. /reporter is a convenience route: a stored Reporter session role redirects to this dashboard, other stored staff roles redirect to the editor queue, and guests go to login with the dashboard as next. This alias does not reread the account; the protected destination enforces the current database role.

The real dashboard route runs isReporter before its controller. It takes the account ID from the session and rereads User.findById(sessionUser._id).select('role').lean() on each protected request. A missing session redirects ordinary HTML requests to /staff/login?next=%2Freporter%2Farticles; a deleted account triggers session destruction and the same login redirect. An account whose current database role is not Reporter receives a 403 error page. API-style requests receive JSON errors instead. Successful checks refresh the session role. Neither query parameters nor hidden controls authorize access.

Sources: server.js, routes/pages.js, middleware/auth.js, models/User.js, middleware/errorHandler.js, controllers/pageController.js.

Server rendering

2. Initial database query and complete HTML

The controller calls Article.find({reporter: user._id}).sort({updatedAt: -1}).lean(). It fetches all owned articles with no limit, skip, or pagination. The reporter/updatedAt index supports the query. It counts statuses in memory, maps rows, and renders pages/reporter/articles.

Template locals are pageTitle: "My Articles", newsroomRole: "Reporter", reporter identity, five status filters with counts, All plus seven categories, mapped articles, and totalArticles. The list is already in the HTML. GET /api/articles/mine exists and returns raw articles, but this dashboard never calls it.

Sources: controllers/pageController.js, models/Article.js, views/pages/reporter/articles.ejs, controllers/articleController.js.

Assets

3. Template composition and startup

The full EJS document includes shared head and newsroom header. It renders the workspace and its own newsroom footer, then loads deferred /js/reporterArticles.js. Shared head loads /css/style.css and deferred /js/api.js, which executes first and supplies window.api.

CSS imports fonts followed by variables, base, utilities, components, layouts, and pages. Page-specific reporter rules live in pages.css; shared workspace offsets live in layouts.css. The table keeps a 1120px minimum width inside its horizontal scroll wrapper. At 1024px filters become a row; below 640px category/search controls wrap to full width. The browser script locates articlesTableBody, statusFilterPills, categorySelect, articleSearchInput, noResultsState, displayedCount, and reporterStatus. It starts activeStatus at All and immediately calls applyFilters.

Sources: views/pages/reporter/articles.ejs, views/partials/shared/head.ejs, views/partials/newsroom/header.ejs, public/css/style.css, public/css/pages.css, public/css/layouts.css, public/js/reporterArticles.js.

Shared component

4. Header logo, navigation, and identity

The newsroom header uses currentUser from the server session. For a Reporter, the logo and My Articles link point to /reporter/articles; New Article points to /reporter/articles/new/edit; View Public Site points to /. All are ordinary links requesting new HTML documents. The header prints currentUser.displayName and the supplied Reporter badge. It does not fetch /api/auth/me.

The shared header has an Editor branch, but a legitimate Editor cannot reach this Reporter-only page. The header’s branch is presentation, not the access check. Sign Out has its own flow below.

Sources: server.js, views/partials/newsroom/header.ejs, views/partials/shared/site-logo.ejs, routes/pages.js.

Component

5. Breadcrumb and Reporter Workspace context

The Newsroom breadcrumb links back to this dashboard; My Articles is the current text. The context bar displays Reporter Workspace, the desk label Newsroom, reporter initials, name, and (Reporter). The controller uses displayName or username and the initials helper takes the first letters of at most two whitespace-separated words. Newsroom is a hardcoded desk label, not a user’s assigned database beat.

Sources: controllers/pageController.js, utils/viewMappers.js, views/pages/reporter/articles.ejs.

Component

6. Heading and New Article action

The heading and description explain that this workspace manages drafts, pending work, and live stories. The New Article button is an anchor with a decorative add_circle icon. Clicking it navigates to /reporter/articles/new/edit.

The destination runs isReporter and renders the new authoring form with no existing Article lookup and an empty ID. Clicking the dashboard link does not call POST /api/articles and does not create a database record. Draft creation and autosave belong to the separate edit-page walkthrough.

Sources: views/pages/reporter/articles.ejs, views/partials/newsroom/header.ejs, routes/pages.js, controllers/pageController.js.

Component

7. Status pills and counts

Initial buttons are All, Draft, Pending Review, Published, and Changes Requested. Counts come from the records’ raw draft-workflow statuses. All starts with .active. The data-status value is the human label, such as Pending Review, which matches each row’s mapped status label.

Clicking a pill or its nested count removes active from other pills, activates the chosen one, updates activeStatus, and reruns the combined filters. No request is sent. Pill counts stay the initial totals across all owned articles; they are not recalculated for category/search. Reloading returns the selection to All. There is no URL state or aria-pressed update in this script.

Sources: controllers/pageController.js, config/constants.js, views/pages/reporter/articles.ejs, public/js/reporterArticles.js.

Component

8. Category selector

The selector contains All, World, Business, Technology, Science, Culture, Sports, and Opinion. All is initially selected. On change, applyFilters reads its value and requires exact row.dataset.category equality unless All/empty. No request or database query is sent, and changing a category preserves the active status and title search.

Categories describe the version used by the row mapper. Uncategorised is a row fallback but is not a dropdown option; those rows appear under All and can still be filtered by status/headline.

Sources: controllers/pageController.js, config/constants.js, views/pages/reporter/articles.ejs, public/js/reporterArticles.js, utils/viewMappers.js.

Component

9. Search by headline

Each input event immediately reruns filtering. The code trims and lowercases the search string, lowercases each row.dataset.title, and uses literal includes. This is substring matching on the rendered headline only; it does not search content, editor notes, or author names. There is no debounce, regex, Enter submission, or API call. Clearing the input removes only the title condition.

The controls are not a submitted search form and selections are not encoded in the URL. All filtering runs over the loaded rows, which currently include every owned article.

Sources: views/pages/reporter/articles.ejs, public/js/reporterArticles.js.

Component and mapping

10. Article rows and version selection

Each row shows headline/thumbnail/detail, category, status, last updated, views, and actions. The mapper uses publishedVersion || draftVersion || {}, not draft-first. Once a publishedVersion object exists, its headline, category, and image remain the table source even while draft changes or an update is pending. Edit still opens the draft.

Titles fall back to (Untitled article), category to Uncategorised, image alt to title or Untitled article. Rows expose data-status, data-category, and data-title for browser filtering. Values use escaped EJS. Thumbnail URLs are normal images without a lazy attribute; missing images render an image_not_supported placeholder. There is no image-error fallback handler.

Returned articles with editorNote show “Editor note: …”; published articles with pending draft updates show “Update awaiting approval — the previous version is still live”; otherwise the detail shows category or No content yet. The mapper produces statusClass, rowClass, detailClass, and actionClass, but this template does not insert those fields. It uses its own status badge and an alert detail modifier for Changes Requested (also an unused Rejected condition).

Sources: utils/viewMappers.js, models/Article.js, views/pages/reporter/articles.ejs, public/js/reporterArticles.js.

Components

11. Last Updated, Views, and result count

Public readership now increments totalViews with {timestamps:false} in the article page controller. A reader visit therefore preserves updatedAt and does not move the story to the top of this dashboard; draft saves and workflow saves still update it.

Last Updated uses Article.updatedAt, not publishedAt: the display helper formats Today/Yesterday/short month-day plus server-local time; time.datetime uses ISO. There is no browser timer to age these labels. Published rows show formatted totalViews (for example 14200 → 14.2k), while never-published rows show a dash. A live article’s views remain visible even if its draft status is Draft or Pending Review.

The bottom count initially reads articles.length of totalArticles, which are equal. applyFilters changes only #displayedCount. This area is styled as pagination but has no page controls or load-more request. Status counts, totals, timestamps, and views remain snapshots until a document reload.

Sources: controllers/pageController.js, utils/viewMappers.js, models/Article.js, views/pages/reporter/articles.ejs, public/js/reporterArticles.js.

Component

12. No matching articles state

#noResultsState begins hidden even when the query returns zero rows. The script’s startup applyFilters reveals it if visible is zero. Later filtering uses the same message: “No articles match the current filters. Try another status or category, or clear the search.” It does not distinguish no owned articles from no matching filters.

The table and column headings stay present. With JavaScript disabled, an empty initial table keeps this message hidden. There is no special first-article onboarding or reset-all-filters button.

Sources: views/pages/reporter/articles.ejs, public/js/reporterArticles.js.

Component

13. Headline link and Edit action

Both the headline and Edit link point to /reporter/articles/:id/edit. The route runs isReporter; reporterEdit queries by both article ID and current reporter ID. Missing or unowned records fall through to 404. The editor form uses draftVersion even if the dashboard headline came from publishedVersion.

The Edit link remains active for Pending Review rows. Navigation succeeds for an owned article but the destination receives locked=true; server draft-save checks also reject Reporter changes while pending. Published rows can open the authoring page to prepare an update. The dashboard offers no delete or analytics link.

Sources: views/pages/reporter/articles.ejs, utils/viewMappers.js, routes/pages.js, controllers/pageController.js, controllers/articleController.js.

Component and request

14. Submit for Review and Re-submit

Draft rows show enabled Submit for Review; returned rows show enabled Re-submit. Pending rows show disabled Awaiting Editor; published-status rows show disabled Live. These states are mapped from raw status, independently of isPublished. A saved update can be draft while its prior version stays public, making submission available again.

The tbody’s delegated click handler finds button[data-submit-id], ignores disabled buttons, disables the clicked button, then sends PATCH with newStatus=pending. There is no confirmation, optimistic row update, spinner, or changed button label. Other rows/filters remain interactive; different article requests can run concurrently.

// Illustrative article ID
PATCH /api/articles/507f1f77bcf86cd799439011/status
Content-Type: application/json
Accept: */*

{"newStatus":"pending"}

Shared sendJSON includes same-origin credentials. Its options spread replaces the initially constructed Accept header for this call, so the fetch default Accept is */*. The /api path still ensures JSON authorization errors. The status endpoint now accepts PATCH only; the previous POST alias was removed.

Sources: views/pages/reporter/articles.ejs, public/js/reporterArticles.js, utils/viewMappers.js, public/js/api.js, routes/articles.js, controllers/articleController.js.

Server and persistence

15. Server transition and response

changeStatus looks up the article by ID. Reporter requests must own it, start in draft or returned, and ask for pending. isDraftComplete requires truthy title, summary, and content plus a category in CATEGORIES; an image is optional. The method uses truthiness, not trimming content whitespace at this point.

Success changes status to pending, clears editorNote, and awaits article.save(). The model timestamps update updatedAt. It leaves publishedVersion, isPublished, publishedAt, publishEvents, and views intact. Submission itself never publishes a new story; the editor workflow must approve it.

// HTTP 200, illustrative draft-only submission
{"success":true,"status":"pending","isPublished":false}

// Submission of an update to an already-live story
{"success":true,"status":"pending","isPublished":true}

The browser awaits the response but does not inspect any response fields. Any successful HTTP response returned by sendJSON leads to location.reload(). Status changes use read/validate/save; this handler does not implement an explicit conditional atomic update or concurrency token.

Sources: controllers/articleController.js, models/Article.js, config/constants.js, public/js/reporterArticles.js.

Document update

16. What changes after submission

After success the whole dashboard reloads. The controller rereads owned records, so the submitted article’s new updatedAt usually moves it toward the top. The row now shows Pending Review and disabled Awaiting Editor; status totals are rebuilt. A live update shows the previous version and pending-update detail.

There is no stored filter state: status returns to All, category/search return to template defaults. If the server save succeeds but the response is lost, catch shows an error and re-enables the old button even though the database may already be pending. A retry can then be rejected; manually reloading reveals current state.

Sources: public/js/reporterArticles.js, controllers/pageController.js, utils/viewMappers.js, views/pages/reporter/articles.ejs.

Component

17. Submission feedback and error paths

#reporterStatus begins empty and state-hidden with role=status and aria-live=polite. On failure api.flash inserts err.message via textContent, reveals the paragraph, and sets error color. The clicked button is re-enabled. No timer clears the message, and starting another attempt does not clear it. No success message appears before reload.

Shared component

18. Sign Out

The shared api.js delegates clicks on #logoutBtn. It disables the button and sends POST /api/auth/logout with no body. The server destroys the session and clears connect.sid. Success returns {success:true,redirect:"/"}, and the browser navigates to the public homepage.

If session destruction fails, the server returns 500 with Sign out failed. The browser merely re-enables the button; it does not show that error in reporterStatus. This flow is separate from submitting an article and its feedback.

Sources: views/partials/newsroom/header.ejs, public/js/api.js, routes/auth.js, controllers/authController.js.

Component and fallback

19. Footer and no-JavaScript behavior

The footer is static “The Daily Web — Internal Newsroom System” markup owned by this page; it does not include the public footer and makes no request.

Without JavaScript, the initial table, counts, links, thumbnails, and footer remain available. Category/search inputs can change visually but do not filter rows. Status buttons do nothing, enabled submission buttons do nothing, and Sign Out does nothing. Edit and New Article links still navigate normally and their server authorization remains active. The empty-table message stays hidden because the startup filter function cannot run.

Sources: views/pages/reporter/articles.ejs, public/js/reporterArticles.js, public/js/api.js.

Learning checks

20. Verification and browser learning steps

With local test data, inspect the initial document and assets in DevTools. Change each filter and confirm no list request occurs. Combine filters, click an enabled submit action, inspect PATCH body/response and the following document reload. Compare a pending row’s disabled action with its still-active Edit link. Test a draft-only story and a previously published update separately.

Verification performed for this update: static review of the branch diff and current routes, authorization middleware, controller query/mapping, model, active EJS partials, browser scripts, and owning CSS. Relative source links and in-document fragment targets were checked. This review confirms the documented implementation paths; it does not claim browser, mocked-controller, or live-database tests.

Limits: no browser layout run, live database persistence check, cross-user session exercise, or concurrency test was performed for this page update. Only this documentation HTML was edited. Draft authoring/autosave and editor approval are destination features for separate walkthroughs.
